# CS 230 Module Eight Journal – Portfolio Reflection

1. Client and Software Requirements

The client for this project was The Gaming Room. They wanted to expand their existing game, Draw It or Lose It, from an Android-only application into a web-based application. The goal was to make the game accessible across multiple devices and support more users.
The system needed to support multiple games, teams, and players. It also required that all names (games, teams, and players) be unique to avoid conflicts. Another important requirement was ensuring that only one instance of the game service exists in memory at a time.


2. What I Did Well

One thing I did well in this project was organizing the system using object-oriented design. I clearly defined the relationships between Game, Team, and Player, and used a base Entity class to avoid repeating code.
I also think I did a good job explaining key concepts like inheritance, encapsulation, and abstraction in my domain model. This made the design easier to understand and showed how the system works as a whole.



3. What Helped Me During Development

The design document helped me a lot when thinking about how the system should be structured. Creating the UML diagram made it easier to visualize how the different parts of the application connect to each other.
Breaking the system into classes and using design patterns like the Singleton pattern also helped me understand how to keep the system organized and avoid issues with multiple instances.



4. What I Would Improve

If I could go back and improve one part of my work, I would expand the system architecture section. I would include diagrams or more detailed explanations of how the frontend, backend, and database interact.
I would also improve scalability planning by adding more detail about how the system would handle a large number of users over time.



5. How I Interpreted User Needs

I focused on understanding the client’s main goals, which were accessibility, scalability, and data consistency. I implemented these needs by designing a web-based system that supports multiple users and ensures unique names for all entities.
Considering user needs is important because it helps create a system that works correctly and provides a good experience. If user needs are ignored, the system may not function properly or meet expectations.



6. My Design Approach and Future Improvements

My approach to designing the software was to break the system into smaller components and define clear relationships between them. I used object-oriented principles to organize the design and ensure it was easy to maintain.
In the future, I would spend more time planning the architecture before starting the design. I would also use more diagrams and consider scalability and performance earlier in the process to create a stronger overall system.
